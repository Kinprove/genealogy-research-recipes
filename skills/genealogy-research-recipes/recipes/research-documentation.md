# Research log and report

Use this reference to preserve the searches and record links in an
[emigrant-origin packet](russian-empire-emigrant-origin-recovery.md).

## Research log

Retain these columns in this order:

```text
Date | Repository | URL / Call # / Microfilm # | Research question / what searched for | Locality | Source citation | Results / Comments / Analysis | Document number
```

Assign each inspected record a local document number, such as `R1`. Record the collection,
place/date coverage, exact query or browsing range, and the result. Link the entry to its
[source citation](source-citation.md) and saved images when available.

Use `NIL` for a completed search with no hits. Record inaccessible images, interrupted searches
and unsearched collections with their actual status. Keep literal record wording and uncertain
readings separate from your interpretation.

Date each NIL against the collection as it stood at the time. Record the collection title and any
coverage or last-updated note the provider showed. A NIL covers only that version. If the provider
later lists the collection as added to or updated, for example with new counties or years, re-run
the logged search as a new dated row. Do not overwrite the old row. The
[Lisa Lisson update-check example](https://www.youtube.com/watch?v=0_GHyojrnu8) motivates this
re-check. An update notice does not show that the target place or period was added, so confirm the
new coverage before expecting a hit.

When a database displays only a fixed maximum number of hits, a list that reaches that cap may be
incomplete, so a target missing from it is untested, not a NIL. Narrow the query, for example to
one record category and one year range at a time, until each slice returns fewer hits than the cap.
Log each slice as its own row with the category and range used. A
[J-Roots database-search tip](https://forum.j-roots.info/viewtopic.php?f=20&t=5084) motivates this
for one site's 100-record display. Check each tool's actual cap. A completed set of slices still
covers only that database.

If searches went unlogged, a browser-history export for that period can list the pages to reopen.
Rebuild each citation and log row from the reopened record page, not from the URL, and mark these
rows as reconstructed after the fact. History lists the URLs of visited pages. It does not show
every query run or every result inspected and dismissed, so do not turn it into NIL entries. The
[Family History Fanatics recovery example](https://www.youtube.com/watch?v=BSOrsobztYY) motivates
this step without naming a tool or making extraction from record pages automatic.

When building a timeline, keep the date as written, its source locator and stated precision
separate from any derived sort key. If software supplies a synthetic first day to order a
month-only date, label that value as an ordering convention and do not export it as the event
date. Preserve qualifiers and ranges in the displayed value. Overlapping uncertain intervals
leave event order unresolved even when the software presents one row before another.
The [timeline-sorting example](https://www.youtube.com/watch?v=8Smljk9Aink) reports a partial
date beside a generated first-of-month value. It motivates this distinction without
establishing a current formula or interface contract.

For a bounded set of multi-person records, an optional associate index can keep one row
per named person's occurrence, with the same source-item/document number on every row from
that item. Filter by person to see their occurrences or by item number to recover its named
participants. Retain documentary roles and unresolved same-name identities. These are
occurrence rows, not additional records or independent confirmations; keep the ordinary log.
The [John Dobkins record-tracking example](https://dna-explained.com/2022/10/16/tracking-john-dobkins-or-dobbins-to-maryland-52-ancestors-378/)
supplies this two-way lookup; repeated association does not establish kinship.

To compare recurrence across record types, derive a matrix from those occurrence rows:
one identified person or unresolved identity candidate per row, and one source item per
column, ordered by the recorded action or observation date. Retain the date and document
number in each column and mark only observed occurrences. Keep uncertain identities
separate rather than merging same-named people to fill the grid. Compare recurring
participants to choose the next distinguishing record; empty cells do not record a
completed search, and multiple columns containing copies remain dependent evidence.
The [Alford/Johnson FAN-chart example](https://familylocket.com/rlp-257-alford-johnson-project-interview-with-michelle-mickelson-part-1/)
supplies the chronological people-by-source view; the identity and blank-cell controls
apply the existing evidence rules. Keep the underlying log and occurrence rows.

Record which names you deliberately searched in each resource, with the date and method.
A name met incidentally while extracting other surnames is an occurrence, not a completed
search for that name; queue that search separately. The [extraction-log example](https://dna-explained.com/2024/06/14/genealogy-proof-series-extracting-and-recording-data-so-that-you-can-find-it/)
motivates this distinction without requiring every name to be transcribed.

For women in a parish's metrical books, a per-surname extraction table can hold two marriage lists
besides family groups: brides born with the surname, and brides who married into it. Record any
prior married surname each entry gives. A widow recorded without a maiden name can then be traced
back one marriage at a time to her first marriage, which states her birth surname. Each link is a
candidate until the original entry is reread. Ages at remarriage may be unreliable, and the lists
cover only the books extracted. A
[metrical-book marriage-table example](https://rodgersforum.borda.ru/?1-0-0-00000238-000-0-0-1721744472=)
demonstrates this chaining.

## Turn locality coverage into the next searches

Keep a locality guide bounded to the question and period: historical jurisdiction, relevant
series and dates, known loss, present custodian, access and collection/finding-aid links.
Include geography or administrative history when it changes where to search. A described
collection remains uninspected until its contents have actually been examined.

List every body that created records for the place and period as a separate line in the guide.
That includes town, school and church bodies, special-purpose districts such as irrigation or
hospital districts, and the county, state and national levels. Records at these levels may contain
different information or copies of the same information; check their creation and copying
relationships. A NIL at one level leaves the others unsearched. When judging who supplied a found document's
information, note which level created it. James Tanner's
[jurisdiction-layer example](https://www.youtube.com/watch?v=7Jn_XMUozo0) motivates this list. It
does not establish that any district's records survive or name individuals.

For conflicting gazetteer coordinates, retain each source's place identifier, stated
reference point, coordinate system and date where supplied. A church, market square or
calculated centre can represent the same settlement; a coordinate difference alone does
not separate two places. Check the described feature and historical context before merging
or separating the candidates, without inventing a distance tolerance. If relocation is
documented, retain the earlier and later sites with their supported dates and identify which
site each source describes. Leave unknown dates or reference points unresolved instead of
replacing an earlier site with today's coordinates. The [2025 historical-place data discussion](https://www.youtube.com/watch?v=yR_W3jjwQAU)
supplies these reference-point and relocation distinctions; their use in this locality guide
is synthesis, not evidence that any particular place moved.

Use that coverage to choose the next searches: target series and locator, dates or sections
to inspect, access route and the observation that could distinguish the competing explanations.
After a local record loss, distinguish copies transmitted to another custodian from records
created separately by another administrative level. In Family Locket's 2022 example, state-held
tax copies and federal land patents supply different routes; a patent does not replace a
subsequent county deed. Verify the relevant custody and survival for the actual locality.

Trace custody series by series across every jurisdiction that controlled the spot during the
record period. After a county split, older records may stay with the parent county, pass to the
new county, go to a state archive or library, or be destroyed. After a border change, church and
land records may have gone to different archives, or originals may have left with emigrants. James
Tanner's [records-move rule](https://www.youtube.com/watch?v=aSwzD902OUE) and Dave Obee's
[border-change example](https://www.youtube.com/watch?v=NQ8E1t7xN4g) motivate this check. Neither
supplies a custody history for any particular place.

For one parish's registers or one revision year, keep a year-by-year holdings list beside the
locality guide. For each year and section, record every known locator, including parallel files in
another inventory or fond. Also record the parish's own page range inside a multi-parish volume and
scope notes such as births, marriages or deaths only, non-confessing only, or near-illegibility.
Cite the page range, not only the volume, and log which file you actually inspected. A year missing
or nearly illegible in one file is not lost or NIL until the parallel files are checked. Where
files are stated to copy each other, treat them as one source, not independent confirmation;
otherwise do not assume parallel files are identical. A
[parish register holdings-list example](https://rodgersforum.borda.ru/?1-7-0-00001326-000-0-0-1780129313=),
a [parish locator table](https://rodgersforum.borda.ru/?1-7-0-00001306-000-0-0-1766240961=) and a
[revision-list duplicate discussion](https://rodgersforum.borda.ru/?1-7-0-00001332-000-0-0-1772787407=)
motivate this. None shows which file is the original, or that copies agree in completeness or
marginal notes.

When searching an archival catalogue or reference database, use the administrative units in force
at the record date, not an earlier or later unit, such as a former sloboda or a Soviet oblast or
raion. A birthplace stated in a unit created after the event uses later terminology; convert it to
the units in force at that date before searching. If the settlement returns nothing, repeat the
search at the enclosing district and then the province, because files covering a whole district may
be indexed only there. A [J-Roots archive-reference discussion](https://forum.j-roots.info/viewtopic.php?f=152&t=36),
a [J-Roots beginners' advice thread](https://forum.j-roots.info/viewtopic.php?f=20&t=5084) and an
[Ural revision-list exchange](https://rodgersforum.borda.ru/?1-14-0-00000139-000-0-0-1767764008=)
motivate this. They do not show how other catalogues index places, and a NIL at every level covers
only the catalogue searched.

**Method origin:** [Family Locket's locality research and planning example](https://familylocket.com/using-the-fan-methodology-to-find-a-females-father-part-2-locality-research-and-research-planning/).
Use [evidence and proof judgment](evidence-proof-judgment.md) to decide what a result changes.

For private family or plantation papers relevant to the locality, use an available collection
index by place, surname or collection to select the described collection and section. Include
collections held elsewhere that mention the place. Follow the locator to the actual holder
and available volume or reel, then read its finding guide before selecting a bounded range
to browse. A guide may describe only part of the contents; an omitted name or item does not
establish absence from the papers. Log the pages actually inspected and leave the remainder
uninspected. Private papers are also a separate lead after courthouse loss; a surviving private
copy must be located, not presumed. Amy Johnson Crow's [2018 plantation-records interview](https://www.youtube.com/watch?v=in4Jda5KglQ)
supplies this index-to-collection route, without establishing present holdings or proving that
the target person appears in a collection.

A genealogical or local-history periodical subject index can supply another locality route.
Search by place and relevant subject category, or a distinctive surname, using the index's
actual options. Preserve the article title, periodical, issue and publisher supplied by a hit;
it is an article citation, not an inspected article. Check the publishing society's holdings
or copy service, then the indexing library's article-copy route if needed, using current
instructions and the exact citation. Keep an unavailable or requested article distinct from
one received and read. Amy Johnson Crow's [2025 PERSI demonstration](https://www.youtube.com/watch?v=Hr6FD9xvNUM)
supplies this citation-to-article handoff; its historical order form and service terms are not
a current ordering contract.

Before an onsite visit, confirm the specific service and target volume for the actual date.
An open building, scheduled tour, onsite finding index and retrieval of original files are
separate arrangements. Retain any advance-order requirement and the permitted capture route;
if only the index can be inspected, preserve its pointer and leave the document queued.
The [onsite-trip example](https://familylocket.com/how-to-prepare-for-an-onsite-genealogy-research-trip/)
motivates this distinction without establishing a repository's current policy or permission.

For a written record request, state the person or event, known dates and places, available
locator, and desired delivery form. If an image of the entry is needed, request a reproduction
of the original explicitly; distinguish the image, transcription or certified extract actually
received in the log and citation. The [2021 civil-register request example](https://www.youtube.com/watch?v=dhDhK3sPgyU)
motivates that product distinction. Check the holder's current service and fee information
before ordering; the example establishes no present fee, service or certification requirement.

## Find a manuscript collection's holder

For a supported manuscript lead, switch to
[manuscript collection recovery](manuscript-collection-recovery.md) for the creator and subject
searches in cross-repository catalogues, the trace from a collection description to the holder's
own catalogue, and the request states. The
[university-archives interview](https://familylocket.com/rlp-284-university-archives-with-sam-howes/)
demonstrates creator and subject searches in ArchiveGrid and reports its incomplete participation.
Use the onsite preparation checks above for any described material you plan to request.

## Recover a dated page behind a dead citation

For a broken link to a historical genealogy page, retain the exact original URL and check
an available web archive, such as the Internet Archive's Wayback Machine, for a dated capture.
Inspect a capture's page content as well as its capture date: several later
captures may preserve only an error page. Move back to a content-bearing capture, then inspect
later available versions for the needed pre-change page. Record the original URL, archive URL
and capture timestamp, inspected dates, access date and actual content or error state; keep any
known original publication date separate and retain any pointer to the underlying source. Record
missing pages, images and linked material individually. No usable capture means the page
remains unavailable. An archived tree or transcription keeps that source role; retrieval adds
neither independent corroboration nor proof of kinship. Roberta Estes's
[2026 broken-link example](https://dna-explained.com/2026/10/02/focus-step-1-seven-solutions-for-dna-matches-with-absent-or-shrunken-trees/)
supplies this recovery route, without guaranteeing a capture or the site's current content.

The [digital-publications demonstration](https://www.youtube.com/watch?v=a-539DY1aak)
shows the temporal search across captures. A surviving page does not mean its search form or
database was preserved: report failed controls and missing captures as retrieval gaps. An
archived page's date or an unavailable search does not establish record absence or the truth
of its claims.

## Keep next actions linked to their origin

When analysis produces another search, retain a separate pending-action field linked to
the originating document number or correspondence entry. Derive a list of nonempty actions
showing that link, a short source description, the proposed search and its repository or
recipient. Group by repository when planning a session. Mark an action completed with its
actual result or link to the new log entry; preserve the originating record and analysis.
This avoids burying a lead in comments or detaching it into an untraceable to-do list.
The [research-log views example](https://familylocket.com/rlp-258-saving-views-of-your-airtable-research-log/)
demonstrates filtering next steps and grouping them by repository. These are companion
views of the log, not replacement search results or a requirement to use Airtable.

## Compare one family across named censuses

An optional grid can place people on rows and selected census years on columns, with each
observed household linked to its own source locator. If a child was enumerated elsewhere,
retain that household reference; distinguish contextual parents from the focus family.
An empty cell is work remaining, not a completed NIL search or evidence of absence. Link
unresolved cells to the next record search. Keep this derivative beside the source log;
unnamed age-bin schedules cannot supply named-person observations.

**Method origin:** [BYU's family timeline-grid demonstration](https://www.youtube.com/watch?v=0p_3oXHBy5I).

## Research report

Retain the originally agreed objective. Show a later working objective as a separate dated
revision with its reason and the scope actually followed, preserving any actual agreement.
Do not rewrite the original objective with facts learned later. This applies the
[research-planning example](https://familylocket.com/rlp-187-revisiting-research-planning-again/)
without imposing an additional approval process.

State the person and question, list the records inspected, and explain which observations
support or contradict each proposed identity, movement or locality. Refer to the document
numbers and citations so another researcher can retrace the analysis.

If the report may be shared in parts, keep the project name, report version date and page
N of M on every page. Keep each figure, table and document number with its citation, so an
extracted page can be traced to the full report. Retain the full report and original images
separately from the sharing copy. The [report-formatting](https://familylocket.com/rlp-249-rlp-with-dna-11-research-reports/)
and [report-sharing](https://familylocket.com/rlp-250-rlp-with-dna-12-whats-next/) examples
motivate these page-level details; a PDF does not prevent alteration or misuse of an excerpt.

Preserve unresolved questions and name the next record that would distinguish the possibilities.
Use [evidence-proof-judgment.md](evidence-proof-judgment.md) to assess identity and conflicts.

## Find earlier projects for a person

An optional person-to-project index can record each project once with its date, objective,
result, unfinished work and links to the report, log and diagrams. Link every identified
person it actually covers. Consult those projects before rebuilding a timeline or source log;
retain the ordinary person-to-source-item index for individual record occurrences.
Track updates to each destination tree separately using observed status: finishing a report
does not establish that every tree was updated. The [project-tracking example](https://familylocket.com/rlp-223-tracking-research-projects-in-airtable/)
supplies this handoff without requiring a particular database or treating custom status
labels as proof grades.

Before extending an earlier phase's log for a new phase, keep a dated copy of that log linked
to the earlier report. Add later observations in a new working copy or as dated rows, so what
was known at the earlier conclusion stays distinguishable. The [research-planning](https://familylocket.com/rlp-247-rlp-with-dna-9-research-planning/)
and [research-log](https://familylocket.com/rlp-248-rlp-with-dna-10-research-logs/) examples
motivate this baseline; a saved log records that phase's scope, not source truth.
