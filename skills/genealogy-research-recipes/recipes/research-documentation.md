# Research log and report

Use this reference to preserve the searches and record links of any investigation, for
example an [emigrant-origin packet](russian-empire-emigrant-origin-recovery.md).

## Reopen a stalled question

Frame the question around the person and the relationship, event or identity to resolve. If a
family story bundles claims, turn its prerequisite into a question with its own evidence. For
example, ask which woman married the subject, then whether the identified woman was a
particular man's daughter [B43]. Keep the parentage claim conditional while the spouse's identity
remains unresolved.

Before opening another collection for a stalled question, inventory the earlier claims the plan
depends on and their cited records. Recheck whether each record concerns the right person and
supports the claim.
Flag inherited assumptions, conflicts and sources held only as indexes or extracts. Put checks
that can remove a premise from the plan near the front, including reading a document already in
hand or retrieving the record behind an extract. Choose a short first round from the wider list.
When a result changes the premise, link the log entry to the affected tasks and record which
searches move up, wait or drop out. Taplin's and Dyer's planning examples illustrate this
sequence [B44], [B45].

## Research log

Retain these columns in this order:

```text
Date | Repository | URL / Call # / Microfilm # | Research question / what searched for | Locality | Source citation | Results / Comments / Analysis | Document number
```

Assign each inspected record a local document number, such as `R1`. Record the collection,
place/date coverage, exact query or browsing range, and the result. Link the entry to its
[source citation](source-citation.md) and saved images when available.

Use `NIL` for a completed search with no hits. Record inaccessible images, interrupted searches
and unsearched collections with their actual status. Keep literal record wording and uncertain
readings separate from your interpretation.

For a faded immigration entry, transcribe what you can read and mark the illegible spans.
Keep the document number and the exact location in the image with the partial reading [B42].

**Privacy gate:** <!-- privacy-gate: publish --> Posting an immigration-record excerpt or question
can expose details about the traveler and other people named in the record to the genealogy forum
or social media group and its audience. Answer the privacy gate in `SKILL.md` first.

If you still need a second reading, post only the cropped, redacted excerpt and the question
needed to read it to a genealogy forum or social media group after clearing the gate. Log each
suggestion with its contributor and check it against the image before adopting it [B42].

A web search-engine query, including a `site:` query, does not search a site's internal database.
Run the site's own search across the name variants (such as Cyrillic е/ё spellings and -ев/-ов
surname endings), and log that venue and query as what was searched; an empty search-engine result
is not a NIL for the site's database.

Date each NIL and record the collection title, years, localities and version or update date shown. When the provider announces an update, check which counties, years or images were added. If the update affects the earlier search, repeat the saved query as a new dated row and keep its predecessor [B1](https://www.youtube.com/watch?v=0_GHyojrnu8).

When a database displays only a fixed maximum number of hits, a list that reaches that cap may be
incomplete, so a target missing from it is untested, not a NIL. Narrow the query, for example to
one record category and one year range at a time, until each slice returns fewer hits than the cap.
Log each slice as its own row with the category and range used. A
[J-Roots database-search tip](https://forum.j-roots.info/viewtopic.php?f=20&t=5084) motivates this
for one site's 100-record display. Check each tool's actual cap. A completed set of slices still
covers only that database.

If a search went unlogged, use the browser history for the relevant dates to reopen the pages that were visited [B3](https://www.youtube.com/watch?v=BSOrsobztYY). Reconstruct the citation and log entry from the record, and label the entry as reconstructed. A visited URL cannot tell you which names you tried or which results you dismissed. Leave an undocumented search open.

If source wording and researcher comments share one field, label the portions `Source` and
`Analysis`. Keep the labels when copying an extract to another note or printing a log. If you
also use colour, keep its legend with the log so the distinction survives a handoff [B46].

When building a timeline, keep the date as written, its source locator and stated precision
separate from any derived sort key. If software supplies a synthetic first day to order a
month-only date, label that value as an ordering convention and do not export it as the event
date. Preserve qualifiers and ranges in the displayed value. Overlapping uncertain intervals
leave event order unresolved even when the software presents one row before another.
The [timeline-sorting example](https://www.youtube.com/watch?v=8Smljk9Aink) reports a partial
date beside a generated first-of-month value. It motivates this distinction without
establishing a current formula or interface contract.

Give each distinct dated statement its own event row when one source supplies several. Repeat
the document number and pinpoint locator, and record what each date refers to. A newspaper can
give a notice date, its publication date and a scheduled hearing date. Label the hearing as
scheduled until a record establishes what happened [B47]. When refreshing a timeline, compare the
document number, locator and dated statement with existing rows before adding them again.

For a set of multi-person records, assign each source item a document number and repeat it on one row per person mentioned. Record the person’s role and keep unresolved identities distinct. Filter by name to find occurrences across documents, then filter by document number to recover everyone named together [B5](https://dna-explained.com/2022/10/16/tracking-john-dobkins-or-dobbins-to-maryland-52-ancestors-378/). Multiple rows from one record add no independent evidence of kinship.

To compare associates across record types, give each identified person or unresolved candidate a row and each dated source item a column. Order the columns by the recorded action or observation and retain their document numbers [B6](https://familylocket.com/rlp-257-alford-johnson-project-interview-with-michelle-mickelson-part-1/). Mark observed occurrences and use recurrent combinations to choose a distinguishing record. A blank cell leaves the occurrence unknown, and copies of a single record remain dependent. Keep the source log and occurrence rows behind the chart.

Log the names actually searched in each resource, with the date and method. If you encountered another surname while extracting records, record the occurrence and queue a separate search before describing that surname as covered [B7](https://dna-explained.com/2024/06/14/genealogy-proof-series-extracting-and-recording-data-so-that-you-can-find-it/).

When records give different names for a person or candidate, log each full name as written with
the record date and citation. Compare the forms in date order. In the next search, start with
forms recorded near the target date, including any middle name or nickname used in the given-name
field [B41]. Keep the recorded forms alongside the working name and check identity against other
details in the records.

For a surname study in parish metrical books, keep separate lists of brides born with the surname and brides who took it at marriage, alongside the family groups [B8](https://rodgersforum.borda.ru/?1-0-0-00000238-000-0-0-1721744472=). When a widow is recorded under a previous husband’s name, follow that marriage back one entry at a time. Look for her birth surname in the first marriage you can establish. Check the spouses, places and chronology against each original, retain age discrepancies and mark any marriage you could not locate.

Retain the sequence of names as written in a deed, will or other list, even when you later create a sorted working table. Record each explicit age or ordinal separately. A will may group sons and daughters or name an executor later; list position alone does not establish birth order. Keep an inferred family order in a separate, sourced analysis [N1](https://genealogytipoftheday.com/index.php/2024/08/29/a-message-to-the-order/), [N2](https://vitabrevis.americanancestors.org/2016/07/birth-order-vs-will-order/).

Log a genealogy.net Metasuche as a bounded metasearch, including the selected databases and any displayed failures. Its current help describes a ten-second wait for replies, not exhaustive completion of every underlying database. If a specific collection matters, search it directly and record that outcome separately; neither a timeout nor a temporarily disabled database is a negative search of its records [N3 @2026-11-16](https://www.pricegen.com/research-around-the-world/), [N4 @2026-11-16](https://meta.genealogy.net/).

## Turn locality coverage into the next searches

Keep a locality guide bounded to the question and period: historical jurisdiction, relevant
series and dates, known loss, present custodian, access and collection/finding-aid links.
Include geography or administrative history when it changes where to search. A described
collection remains uninspected until its contents have actually been examined.

For an initial U.S. county survey, search by place in the FamilySearch Catalog with availability set
to Any. Check each relevant entry's access route, including physical holdings and restricted images
[B37 @2026-11-20]. Then use Ancestry's Card Catalog location and record-type filters to look for
additional collections [B38 @2026-11-20]. If military records could answer the question, check
Fold3 by conflict [B39 @2026-11-20]. This order follows a suggestion from the available excerpt
[B36 @2026-11-20]. Add each relevant collection's coverage and access route to the locality guide.

List every body that created records for the place and period as a separate line in the guide.
That includes town, school and church bodies, special-purpose districts such as irrigation or
hospital districts, and the county, state and national levels. Records at these levels may contain
different information or copies of the same information; check their creation and copying
relationships. A NIL at one level leaves the others unsearched. When judging who supplied a found document's
information, note which level created it. James Tanner's
[jurisdiction-layer example](https://www.youtube.com/watch?v=7Jn_XMUozo0) motivates this list. It
does not establish that any district's records survive or name individuals.

For conflicting gazetteer coordinates, retain each source's place identifier, stated
reference point, coordinate system and date where supplied. A church, market square or
calculated centre can represent the same settlement; a coordinate difference alone does
not separate two places. Check the described feature and historical context before merging
or separating the candidates, without inventing a distance tolerance. If relocation is
documented, retain the earlier and later sites with their supported dates and identify which
site each source describes. Leave unknown dates or reference points unresolved instead of
replacing an earlier site with today's coordinates. The [2025 historical-place data discussion](https://www.youtube.com/watch?v=yR_W3jjwQAU)
supplies these reference-point and relocation distinctions; their use in this locality guide
is synthesis, not evidence that any particular place moved.

Choose the next search by recording the series, dates, access route and observation that would distinguish the competing explanations. After a local record loss, check whether a copy was sent outside the county or a different office created a related record. For Izard County, Arkansas, Elder identified state-held tax lists and proposed federal patents for the initial land grant. Later sales still require county deeds or separate evidence of a transfer [B18](https://familylocket.com/using-the-fan-methodology-to-find-a-females-father-part-2-locality-research-and-research-planning/). Confirm the series and survival for the place in question.

Trace custody series by series across every jurisdiction that controlled the spot during the
record period. After a county split, older records may stay with the parent county, pass to the
new county, go to a state archive or library, or be destroyed. After a border change, church and
land records may have gone to different archives, or originals may have left with emigrants. James
Tanner's [records-move rule](https://www.youtube.com/watch?v=aSwzD902OUE) and Dave Obee's
[border-change example](https://www.youtube.com/watch?v=NQ8E1t7xN4g) motivate this check. Neither
supplies a custody history for any particular place.

For one parish's registers or one revision year, keep a year-by-year holdings list beside the
locality guide. For each year and section, record every known locator, including parallel files in
another inventory or fond. Also record the parish's own page range inside a multi-parish volume and
scope notes such as births, marriages or deaths only, non-confessing only, or near-illegibility.
Cite the page range, not only the volume, and log which file you actually inspected. A year missing
or nearly illegible in one file is not lost or NIL until the parallel files are checked. Where
files are stated to copy each other, treat them as one source, not independent confirmation;
otherwise do not assume parallel files are identical. A
[parish register holdings-list example](https://rodgersforum.borda.ru/?1-7-0-00001326-000-0-0-1780129313=),
a [parish locator table](https://rodgersforum.borda.ru/?1-7-0-00001306-000-0-0-1766240961=) and a
[revision-list duplicate discussion](https://rodgersforum.borda.ru/?1-7-0-00001332-000-0-0-1772787407=)
motivate this. None shows which file is the original, or that copies agree in completeness or
marginal notes.

When searching an archival catalogue or reference database, use the administrative units in force
at the record date, not an earlier or later unit, such as a former sloboda or a Soviet oblast or
raion. A birthplace stated in a unit created after the event uses later terminology; convert it to
the units in force at that date before searching. If the settlement returns nothing, repeat the
search at the enclosing district and then the province, because files covering a whole district may
be indexed only there. A [J-Roots archive-reference discussion](https://forum.j-roots.info/viewtopic.php?f=152&t=36),
a [J-Roots beginners' advice thread](https://forum.j-roots.info/viewtopic.php?f=20&t=5084) and an
[Ural revision-list exchange](https://rodgersforum.borda.ru/?1-14-0-00000139-000-0-0-1767764008=)
motivate this. They do not show how other catalogues index places, and a NIL at every level covers
only the catalogue searched.

**Method origin:** [Family Locket's locality research and planning example](https://familylocket.com/using-the-fan-methodology-to-find-a-females-father-part-2-locality-research-and-research-planning/).
Use [evidence and proof judgment](evidence-proof-judgment.md) to decide what a result changes.

For private family or plantation papers relevant to the locality, use an available collection
index by place, surname or collection to select the described collection and section. Include
collections held elsewhere that mention the place. Follow the locator to the actual holder
and available volume or reel, then read its finding guide before selecting a bounded range
to browse. A guide may describe only part of the contents; an omitted name or item does not
establish absence from the papers. Log the pages actually inspected and leave the remainder
uninspected. Private papers are also a separate lead after courthouse loss; a surviving private
copy must be located, not presumed. Amy Johnson Crow's [2018 plantation-records interview](https://www.youtube.com/watch?v=in4Jda5KglQ)
supplies this index-to-collection route, without establishing present holdings or proving that
the target person appears in a collection.

A genealogical or local-history periodical subject index can supply another locality route.
Search by place and relevant subject category, or a distinctive surname, using the index's
actual options. Preserve the article title, periodical, issue and publisher supplied by a hit;
it is an article citation, not an inspected article. Check the publishing society's holdings
or copy service, then the indexing library's article-copy route if needed, using current
instructions and the exact citation. Keep an unavailable or requested article distinct from
one received and read. Amy Johnson Crow's [2025 PERSI demonstration](https://www.youtube.com/watch?v=Hr6FD9xvNUM)
supplies this citation-to-article handoff; its historical order form and service terms are not
a current ordering contract.

Before an onsite visit, confirm the specific service and target volume for the actual date.
An open building, scheduled tour, onsite finding index and retrieval of original files are
separate arrangements. Retain any advance-order requirement and the permitted capture route;
if only the index can be inspected, preserve its pointer and leave the document queued.
The [onsite-trip example](https://familylocket.com/how-to-prepare-for-an-onsite-genealogy-research-trip/)
motivates this distinction without establishing a repository's current policy or permission.

For the cotes already on the visit worklist, check the target archive's current per-order and
daily request limits, where applicable, and when requests are collected and documents delivered.
Prioritize the cotes within that capacity and retrieval schedule, allowing time to examine each
item; leave work exceeding the day's capacity queued. Keep each cote attached to its notes and
saved images through the permitted capture route. The
[departmental-archive visit tutorial](https://www.youtube.com/watch?v=nveyeh3OT1k) describes local
request limits and retrieval rounds. It motivates this capacity check; do not copy its example
numbers or assume the whole worklist can be retrieved in one day.

For a written record request, state the person or event, known dates and places, available
locator, and desired delivery form. If an image of the entry is needed, request a reproduction
of the original explicitly; distinguish the image, transcription or certified extract actually
received in the log and citation. The [2021 civil-register request example](https://www.youtube.com/watch?v=dhDhK3sPgyU)
motivates that product distinction. Check the holder's current service and fee information
before ordering; the example establishes no present fee, service or certification requirement.

Take the addressee, the answering department and the intake channel (e-mail, web form, portal
account, post) from the holder's official site, and record the URL and check date. Never build an
e-mail address from a domain pattern. Prepare a mailbox draft only where e-mail intake is stated;
otherwise prepare text to paste into the form. Do not send one request to every institution: write
only where there is a reason to think it holds the record or is the competent reference body. Never
state a degree of kinship, representative authority, address or signature the user has not given,
and present family tradition and hypotheses as such, apart from documented facts. When a form
requires a child's name and the names are unknown, never enter a guessed name, because the archive
may search only that name. Give the parents, the place and a reasoned period, and ask whether a
search for the couple's children is possible and on what terms. A negative reply for one name does
not exclude other children.

For a supported manuscript lead, switch to

searches in cross-repository catalogues, the trace from a collection description to the holder's

Use the onsite preparation checks above for any described material you plan to request.

## Recover a dated page behind a dead citation

Keep the exact URL of a broken citation and look it up in a web archive [B24](https://dna-explained.com/2026/10/02/focus-step-1-seven-solutions-for-dna-matches-with-absent-or-shrunken-trees/). Inspect the page itself. When a later capture contains an error, work backwards to a content-bearing version and then compare later captures for the last usable copy. Record the original URL, archive URL, capture time, access date and what was visible. Keep any original publication date separate, and log missing pages, links and images individually [H4]. A retrieved family tree remains an authored account of its claims. If there is no usable capture, leave the cited page unavailable.

The [digital-publications demonstration](https://www.youtube.com/watch?v=a-539DY1aak)
shows the temporal search across captures. A surviving page does not mean its search form or
database was preserved: report failed controls and missing captures as retrieval gaps. An
archived page's date or an unavailable search does not establish record absence or the truth
of its claims.

For a Ukrainian museum, library, archive or Jewish-genealogy site that has gone offline since
2022, also search SUCHO (Saving Ukrainian Cultural Heritage Online) before calling its
collections lost. A Wayback capture of such a site often holds only its start page or other top
layers, not the digital collections [H1 @2026-11-12] [H2 @2026-11-12]. Since February 2025 all
of SUCHO's archived content, more than 50 TB from national archives to local museums, is reached
through the SUCHO Database of Web-Archived Content (`database.sucho.org`), which gives each
resource's online status, collection timeline and completeness [H3 @2026-11-12]. In 2022 the
archived sites already included Gesher Galicia, JewishGen Ukraine and Rohatyn Jewish Heritage
[H1 @2026-11-12]. Record which archive held the capture and its stated completeness, as for any
capture above.

## Keep next actions linked to their origin

When analysis produces another search, retain a separate pending-action field linked to
the originating document number or correspondence entry. Derive a list of nonempty actions
showing that link, a short source description, the proposed search and its repository or
recipient. Group by repository when planning a session. Mark an action completed with its
actual result or link to the new log entry; preserve the originating record and analysis.
This avoids burying a lead in comments or detaching it into an untraceable to-do list.
The [research-log views example](https://familylocket.com/rlp-258-saving-views-of-your-airtable-research-log/)
demonstrates filtering next steps and grouping them by repository. These are companion
views of the log, not replacement search results or a requirement to use Airtable.

Give each sent request its own dated correspondence entry. Retain the channel, the
question asked and a private locator for the message. Link each reply to the request and
record what the sender actually confirmed, including the scope they checked if stated.
Carry an unanswered request as pending, and log a follow-up as a new dated entry linked to
the earlier exchange. A sent message documents the request. The reply, if any, supplies the
respondent's information [B50].

### Reconcile every task before producing an archive visit list

For each event task, retain the person/event identifier, target record, archive
or custodian, locator or clue, project, entered research status, and the actual
searched scope and result. Keep the evidence and task status separate: a status
such as complete or unfindable does not prove source exhaustion.

Before planning a visit, save an all-status inventory and the needed/in-progress
work list for the same project, people, events and snapshot. Compare task
identifiers, not just row counts. For every task present only in the all-status
inventory, record its status and whether its omission is intentional. Check
tasks left at a default such as no research needed even when their target and
archive fields are populated.

Correct an erroneous status with a reason, then regenerate and reconcile the
work list. Preserve intentional exclusions and unresolved exceptions. The
visit list should link back to the complete inventory and show which settings
produced it. A nonempty action list by itself does not establish completeness.

In a next-steps list, mark each proposed source's access as checked, with date and URL, or as
unverified. Never state from memory that a series is online, for example that a village's 1858
revision lists are online. Say what each step would settle and what it depends on, and give cost
or turnaround only when known.

## Compare one family across named censuses

An optional grid can place people on rows and selected census years on columns, with each
observed household linked to its own source locator. If a child was enumerated elsewhere,
retain that household reference; distinguish contextual parents from the focus family.
An empty cell is work remaining, not a completed NIL search or evidence of absence. Link
unresolved cells to the next record search. Keep this derivative beside the source log;
unnamed age-bin schedules cannot supply named-person observations.

**Method origin:** [BYU's family timeline-grid demonstration](https://www.youtube.com/watch?v=0p_3oXHBy5I).

## Research report

Retain the originally agreed objective. Show a later working objective as a separate dated
revision with its reason and the scope actually followed, preserving any actual agreement.
Do not rewrite the original objective with facts learned later. This applies the
[research-planning example](https://familylocket.com/rlp-187-revisiting-research-planning-again/)
without imposing an additional approval process.

State the person and question, list the records inspected, and explain which observations
support or contradict each proposed identity, movement or locality. Refer to the document
numbers and citations so another researcher can retrace the analysis.

Before finishing the report, compare names, dates, places and relationships repeated from the
original objective with the findings. If the evidence supports a correction, label the earlier
identifier as superseded where the original wording is retained. If the conflict is open, flag it
in the current summary. Dyer reported that a draft kept the initial death date in its objective
even though the findings in the same report gave a different date [B48].

Keep search details in the log. In the report, summarize negative searches by record series or
question when they help evaluate a proposed answer, explain a change of route, or establish what
remains open. Give the scope and a pointer to the log rows. If you used a derivative because the
original could not be inspected, state both the positive finding and the limit on the original.
A Family Locket example uses footnotes to retain relevant negative searches without turning
the report into a chronological list of queries [B49].

For a family-history scrapbook, draft the narrative along the subject's life timeline. If
portraits are scarce, use record images, gravestone photos or relevant book and newspaper extracts.
Keep the source locator with each and turn gaps exposed by the draft into specific questions
tied to the timeline [B40].

**Privacy gate:** <!-- privacy-gate: contact --> A question sent to a living relative may disclose
details about the subject or other living people to that relative. Answer the privacy gate in
`SKILL.md` first.

After clearing the gate, ask a living relative who may know the missing detail through a route
allowed by the [Living people rule](../SKILL.md#living-people). Record any recollection with
the speaker and date, and leave unresolved details open [B40].

**Privacy gate:** <!-- privacy-gate: publish --> Handing or sharing the report, in full or in parts,
exposes what it says about living relatives to family members and other readers; answer the
privacy gate in `SKILL.md` first.

Give the summary, captions, chart and "how we are related" chain the same qualifier as the body,
and never a higher status than the working notes: a front page saying "fought in WWI" over a
chapter saying "almost certainly" fails this. Give each parent-child link in the chain its own
label, the reason the records concern the same person, and the namesakes excluded. For a chart
that still asserts a disputed link, see
[evidence and proof judgment](evidence-proof-judgment.md#using-working-hypotheses-without-inheriting-their-assumptions).
Before handing the report to the family, re-read it as a reader with no context of the case,
looking for confused names and unexplained terms.

Report sensitive findings neutrally, as documented facts with their sources and no evaluative
comment. This covers children's birth dates against the parents' marriage-registration date,
repression, criminal records, and ethnicity or confession. Give the dates and entries; do not
characterise a birth before the registration date, or a conviction. For an unexpected parentage
finding, follow the disclosure care in [unknown parentage and WATO](unknown-parentage-wato.md).

If the report may be shared in parts, keep the project name, report version date and page
N of M on every page. Keep each figure, table and document number with its citation, so an
extracted page can be traced to the full report. Retain the full report and original images
separately from the sharing copy. The [report-formatting](https://familylocket.com/rlp-249-rlp-with-dna-11-research-reports/)
and [report-sharing](https://familylocket.com/rlp-250-rlp-with-dna-12-whats-next/) examples
motivate these page-level details; a PDF does not prevent alteration or misuse of an excerpt.

Preserve unresolved questions and name the next record that would distinguish the possibilities.
Use [evidence-proof-judgment.md](evidence-proof-judgment.md) to assess identity and conflicts.

## Find earlier projects for a person

An optional person-to-project index can record each project once with its date, objective,
result, unfinished work and links to the report, log and diagrams. Link every identified
person it actually covers. Consult those projects before rebuilding a timeline or source log;
retain the ordinary person-to-source-item index for individual record occurrences.
Track updates to each destination tree separately using observed status: finishing a report
does not establish that every tree was updated. The [project-tracking example](https://familylocket.com/rlp-223-tracking-research-projects-in-airtable/)
supplies this handoff without requiring a particular database or treating custom status
labels as proof grades.

Before extending an earlier phase's log for a new phase, keep a dated copy of that log linked
to the earlier report. Add later observations in a new working copy or as dated rows, so what
was known at the earlier conclusion stays distinguishable. The [research-planning](https://familylocket.com/rlp-247-rlp-with-dna-9-research-planning/)
and [research-log](https://familylocket.com/rlp-248-rlp-with-dna-10-research-logs/) examples
motivate this baseline; a saved log records that phase's scope, not source truth.
