# Recipe: Recover and inventory a U.S. military pension file

## Goal

Move from a military-service clue or pension index card to the appropriate application file,
then inventory the received documents and the progression of the claim. Preserve the distinction
between an index, a service record, a pension file and an abbreviated copy product.

## Before starting

List the person's supported name forms, residence, approximate service period, branch and unit
when known. Mark a family story or uncertain service identification as a lead. Keep competing
soldiers separate. Choose a research question that the pension documents could answer.

This workflow concerns historical pension applications. It does not establish benefit eligibility
or replace the current instructions for requesting recent military personnel records.

## 1. Choose the record type and present custodian

1. Compare the service clue with a conflict, branch and unit. Save the source of that context;
   an unusual name alone does not establish the correct soldier.
2. Search a pension index covering the relevant service and claimant category. Do not assume
   every person who served applied for a pension.
3. Distinguish the pension application from the service record and any bounty-land application.
   Record which of these you are trying to retrieve.
4. Consult the current repository instructions before choosing a request route. NARA's older-record
   page separates service requests from pension/bounty-land requests; NATF 85 concerns eligible
   federal pension/bounty-land applications, rather than state or Confederate pensions.
5. For a state or Confederate pension lead, identify the relevant state's custodian and holdings.
   For a transferred file or uncertain repository, ask the custodian with the copied identifiers
   instead of treating a historical storage rule as a current guarantee. [S1, S3, H1, H2]

**Artifact:** A routing row: candidate ID, service evidence, conflict/branch/unit, record type,
claimant category, index/series coverage, current custodian, retrieval route and date checked.

**Check:** A service record is not a pension file. A pension-index miss describes that search,
not proof that no application exists in any series.

## 2. Preserve the complete index-card locator

1. Open the index image when available. Copy the soldier and applicant names, service designation,
   claim category, application number and certificate number exactly as supplied.
2. Preserve prefixes, suffixes, filing dates, residence/state, transfer marks and marginal notes.
   Do not combine an application's number with another claimant's or category's certificate.
3. Keep the index collection/series, card/image locator and a saved image where permitted.
4. Compare the card's service and applicant context with the intended candidate.
5. Continue investigating an application with no certificate number or a rejection notation.
   It may still have an application file and subsequent supporting documents; do not report
   “no file” solely from an unsuccessful claim.
6. If a mark suggests transfer, carry its exact wording into a custody inquiry. This recipe does
   not assign a universal meaning or current storage location to every prefix. [S1, S2, S3]

**Artifact:** An index-locator table with a separate row per candidate and claim/category.

**Check:** The request identifies the intended claimant and application. An index card supplies
a locator; it does not substitute for reading the application documents.

When another index-card version or series is actually available for the same supported claim,
compare its image with the first card. A later file identifier may appear on one version and be
absent on another; the interview in S4 illustrates this with an XC number. Keep each collection,
card locator, available filing/transfer dates and number separately, preserving both images
where permitted. Carry an additional identifier into the custody check without overwriting the
earlier application/certificate locator. An unresolved mismatch remains open; a missing field on
one card does not establish that no later identifier exists. Do not assume a particular website
always supplies the fuller card or that a prefix establishes the file's present location. [S4]

## 3. Obtain the intended file product and record its limits

1. Check whether the result is only an index image, a selected extract, or a multi-image
   application file. Inspect its description and image sequence rather than its search-result title.
2. Compare multiple apparent file matches against the locator table; a name can produce more than
   one candidate file.
3. If ordering eligible older federal pension records, use NARA's current pension request
   instructions and the identifiers you copied. Its product choices distinguish a complete
   application file from a Pension Documents Packet containing selected document types.
4. Choose the product that fits the question. For a question requiring the claim's progression
   or witness material, request the complete-file option rather than silently substituting the
   smaller packet.
5. Record the selected product, request identifier, submission date, custodian and any page limit
   or remaining-copy instructions in the actual order. Check current terms instead of carrying
   a video's historical price or delivery estimate into the request.
6. When copies arrive, record what was received and any stated omissions. Follow up on a
   disclosed page limit or incomplete delivery when the missing material affects the question.
   [S1, H1]

**Artifact:** A retrieval receipt: file identifiers, product requested, online/download/request
route, request date/ID, expected scope, received files/images and disclosed limits.

**Check:** “Complete” in a product name is not your image-count or delivery verification.
Record the actual package and unresolved omissions. Do not claim a request was sent unless it was.

When identifiable prior copies, dated notes or internal references describe particular papers,
compare them with the newly received package. Queue each unmatched item with its earlier
locator or observation basis and its current retrieval status. Keep absent testimony unrecovered;
a note about it does not recreate the document. The [Sarah Cook re-retrieval example](https://dna-explained.com/2023/01/09/sarah-cook-1774-1775-1863-epitome-of-perseverance-52-ancestors-386/)
motivates this comparison without establishing misfiling or the missing paper's contents.

## 4. Inventory the pages and reconstruct the claim's sequence

1. Read the received file through once, including covers, administrative notes, rejected claims
   and reconsideration material.
2. Give each received image a stable ID in its original order. Group connected pages into
   documents while preserving every image's original locator.
3. Record the document type, date, creator, applicant and named people; distinguish an asserted
   relationship from your interpretation.
4. Create a chronological view of the documents without renaming away the original order.
   Track applications, supplied proof, objections, decisions and later actions when present.
5. Transcribe relevant passages with uncertain readings marked, and check them against the image.
6. End with a claim-action timeline, source-linked leads and explicit gaps. Send identity,
   relationship or conflicting-evidence conclusions to the evidence/proof workflow. [S1, S2]

**Artifact:** Two linked tables:

| Table | Fields |
| --- | --- |
| Image/document inventory | Image ID, original order/locator, document ID, type, date, creator, reading status |
| Claim-action timeline | Date, action/decision as written, claimant, linked document IDs, named-person leads, unresolved question |

**Check:** An early rejection may be followed by further submissions or a later decision.
Read the received sequence before describing the outcome; never turn missing pages into an inferred
final disposition.

## Prompt pattern

> From these service clues and pension-index images, build separate candidate routing and
> locator rows. Identify the current record-type/custodian route without assuming a card is the
> file. Prepare the appropriate request with the exact identifiers and product scope; do not
> claim it was submitted. For supplied file images, preserve original order, inventory every
> image/document and build a claim-action timeline. Retain rejected applications, transfer marks,
> uncertain readings and gaps. Do not decide identity or benefit entitlement.
